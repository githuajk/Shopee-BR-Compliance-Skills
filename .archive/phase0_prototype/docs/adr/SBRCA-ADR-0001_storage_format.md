# SBRCA-ADR-0001 内部持久化格式仅限 JSON 与 Markdown

| 字段 | 值 |
|---|---|
| 决策编号 | `SBRCA-ADR-0001` |
| 版本 | 1.0.0 |
| 状态 | **Draft — 待用户审批** |
| 日期 | 2026-10-27 |
| 决策者 | 技术负责人（Agent），待用户确认 |
| 相关 | 章程 §2.2；`SBRCA-P1-003` §1 |

## 背景

章程 §2.2 规定项目内部持久化数据与文档只允许 JSON 与 Markdown；YAML / JSONL / CSV / TXT / XML 不得作为内部正式数据源。外部输入可以是多种格式。

冲突点：2026-09-15 的历史合规审计线使用 SQLite（`risk_words_FINAL.db`，36,372 词，FTS5 全文索引）存储词库。SQLite 不在允许清单内。

## 可选方案

| 方案 | 说明 |
|---|---|
| A | 严格照章：SQLite 一律不用，索引全部在内存构建 |
| B | JSON 为唯一权威源；允许 SQLite 作为**可再生的派生索引**（可随时删除重建） |
| C | 允许 SQLite 作为正式存储（违反章程明文） |

## 评估标准

格式政策符合度；可追溯性（权威源唯一）；性能可行性（10 万词级）；维护成本；迁移成本。

## 最终选择

**方案 A**（严格照章），并附条件：若 Phase 3 基准测试证明纯内存索引无法满足经批准的阈值，则**以变更请求**升级为方案 B（需用户批准并更新本 ADR）。

## 选择理由

1. 章程是用户明确下达的最高优先级指令，§2.2 的措辞是「不得用作项目内部正式数据源」—— 派生索引是否属于「正式数据源」存在解释空间，不应自行扩大解释。
2. 派生索引方案虽合理，但需要用户先确认「权威源唯一」这一约束的确切边界。
3. Phase 3 基准测试尚未执行，现在就引入 SQLite 属于未经论证的技术选型（违反章程 §8.2 精神）。
4. 方案 C 直接违反明文，排除。

## 风险与代价

- 纯内存 Aho-Corasick 在 10 万词下的内存占用与加载时间**未实测**，可能不达标。
- 若 Phase 3 需引入 SQLite，将产生一次架构变更（需迁移方案 + 新 ADR）。
- 代价可控：SQLite 索引是派生层，引入/移除不影响权威数据。

## 回滚或替代条件

- **触发条件**：Phase 3 基准显示内存索引不达经批准阈值。
- **替代方案**：方案 B（派生索引），并同步更新 `SBRCA-P1-003` §1 与本 ADR。
- **回滚**：删除派生索引文件即可，权威 JSON 不受影响。
