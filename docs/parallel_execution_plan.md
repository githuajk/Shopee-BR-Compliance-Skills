## 3. 并行安全规则

### 3.1 路径零重叠

同一并行波次内的任务，**`allowed_paths` 交集必须为空**。已在注册表中逐条核对：

| 波次 | 任务对 | 路径交集 | 状态 |
|---|---|---|---|
| 2 | POLICY-01 ∩ INGEST-01 | ∅ | ✅ |
| 3 | LISTING-01 ∩ DUP-01 | ∅ | ✅ |
| 3 | LISTING-01 ∩ IP-01 | ∅ | ✅ |
| 3 | LISTING-01 ∩ REPORT-01 | ∅ | ✅ |
| 3 | DUP-01 ∩ IP-01 | ∅ | ✅ |
| 3 | DUP-01 ∩ REPORT-01 | ∅ | ✅ |
| 3 | IP-01 ∩ REPORT-01 | ∅ | ✅ |

> 唯一潜在冲突是 `rules/03` —— 已通过「只提拆分建议、不直接改」消除。

### 3.2 工作区隔离

**当前工作区无 Git 仓库**（已核实）。

| 方案 | 做法 | 适用 |
|---|---|---|
| A（推荐） | 每个 Agent 用独立目录 `/tmp/sbrca_work/<TASK_ID>/`，完成后由集成 Agent 合并 | 当前状态 |
| B | 集成 Agent 初始化本地 Git，各 Agent 用 `git switch -c task/<TASK_ID>` | 需要 PR 流程时 |
| C | 集成 Agent 初始化本地 Git，各 Agent 用 `git worktree add` | 需要完全隔离的检出时 |

**方案 B/C 需要先初始化 Git 仓库** —— 属独立决策，本轮未执行（章程禁止未经授权初始化远程仓库；本地仓库亦需用户确认）。

### 3.3 合并顺序

```
1. 各 Agent 交付（在自己的工作区）
2. 集成 Agent 逐个检查：白名单、契约符合、引文核验、测试输出
3. 通过的按波次顺序合并
4. 冲突的退回该 Agent（附具体原因）
5. 全部合并后跑集成验收
```

**不按 Agent 到达顺序合并** —— 按波次顺序，避免后波次依赖未就绪。

## 5. 风险与缓解

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R1 | 两个 Agent 都需要同一规则文件（`rules/03`） | 并发写冲突 | 只提拆分建议，集成阶段统一拆分 |
| R2 | 契约缺口在某模块实现中途暴露 | 该模块返工 | 变更建议流程（`AGENT_COLLABORATION.md` §4.1）—— 但**不因此直接改契约**，先评估影响面 |
| R3 | 模块间语义漂移（各自理解「重复」不同） | 整合时结论冲突 | 契约定义术语；集成阶段做接口一致性检查（C4） |
| R4 | 引文核验在模块实现时失败 | 规则不能 active | 改为 `unverified` 并在交付说明中记录；不伪造引文 |
| R5 | 夹具不足导致反例缺失 | 规则过宽无法发现 | `tests/fixtures/` 由集成 Agent 统一补；模块提建议 |
| R6 | 无 Git 导致合并冲突难处理 | 合并成本高 | 先用独立目录 + 文本合并；必要时提请初始化本地仓库 |
| R7 | 4 个 Agent 并行时上下文互相污染 | 质量下降 | 严格的工作区隔离 + 契约先行 + 不依赖模型内部记忆 |
