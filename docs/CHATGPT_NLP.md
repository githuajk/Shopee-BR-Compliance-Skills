# 在 ChatGPT 网页版用自然语言做合规审核（不跑代码）

| 字段 | 值 |
|---|---|
| 文档 ID | `SBRCA-DOC-CHATGPT-NLP-001` |
| 版本 | 1.0.0 |
| 创建/更新 | 2026-10-29 |
| 面向对象 | ChatGPT 网页版用户（**Python 沙箱不能联网**的环境） |
| 前提 | ChatGPT **能浏览网页**（能读 raw.githubusercontent.com） |

---

## 1. 为什么是这个方案

你实测过的情况：

- ✅ ChatGPT **能**打开 GitHub 页面、能读 `raw.githubusercontent.com` 的文本
- ❌ Python 沙箱**不能**联网（`Could not resolve host: github.com`）
- ❌ 不想每次上传 ZIP

**所以关键不是"让代码跑起来"，而是"让规则进入 ChatGPT 的上下文"。**

ChatGPT 网页版可以读网页 —— 那就把**判定规则本身**做成一个网页，让它读进去，然后直接用自然语言审。

---

## 2. 怎么用（两步）

### 第 1 步：贴这句话

```
读取 https://raw.githubusercontent.com/githuajk/Shopee-BR-Compliance-Skills/main/docs/CHATGPT_PROMPT.md
并严格按照它的规则审核我下面提供的商品。
```

> **入口文档是自适应的。** 它开头有一段「§A 能力探测与分流」——
> ChatGPT 读完后会自己判断当前环境能做到哪一级，然后选对应的方式审：
>
> | 它能做到 | 会走 | 准确度 |
> |---|---|---|
> | 完整 shell + 能联网 | **T4** 跑真实规则引擎 | **最高** |
> | 能跑 Python、取不到仓库 | **T3** 用文档词表自己写扫描器 | 高 |
> | 能读多个文件 | **T2** 按需读补充文件 | 高 |
> | 只能读这一个文件 | **T1** 纯自然语言判定 | 中高 |
>
> 所以**同一句话对所有环境都成立** —— 不需要你替它判断环境能力。
> 它也会在报告开头声明自己用了哪一级（§A.5），不会让你误以为它跑了引擎。

### 第 2 步：贴商品

直接贴文本就行，**不需要是文件**：

```
商品 1
标题：Creme Anti-Idade Facial com Vitamina C - Reduz Rugas
详情：Creme com 100% garantia de resultado. Cura acne em 3 dias.

商品 2
标题：Faca de Cozinha em Aço Inox
详情：Faca profissional de cozinha, lâmina de 20cm.
```

**没有文件、没有格式要求、没有路径。**

> 想让它读 `.xlsx` 也可以 —— ChatGPT 网页版能读上传的表格，只是**这一步仍然用自然语言**，不跑代码。

## 3. 为什么这个方案可行

关键在于**词库的构成**。整个 `lexicon/term_groups.json` 有 21 万词，但它们分两类：

| 类别 | 组数 | 词条数 | 是什么 | 要不要进 prompt |
|---|---|---|---|---|
| **规则型** | 68 | **1,439** | 真正的触线判定词（arma、cura、garantia、Nike…） | ✅ **全部进** |
| **目录型** | 37 | 209,051 | ANVISA 注册名录（已备案的商品名/厂家名） | ❌ 不进 |

**目录型那 20 万词是"注册过的东西"，不是违规信号** —— 塞进 prompt 既超长又没用。

真正决定判定的 1,439 个词，加上豁免清单、改写对照表、严重度规则、输出格式，总共 **46 KB** —— 完全塞得进上下文。

这就是为什么这份判定手册能成立，而"把整个仓库塞进 ChatGPT"不成立。

## 4. 这份手册里有什么

`docs/CHATGPT_PROMPT.md`（46 KB，979 行）：

| 节 | 内容 |
|---|---|
| §0 | 任务定义 + **三条铁律**（命中≠违规 / 缺信息≠通过 / 不下架） |
| §1 | 九步审核流程 + 类目识别表 |
| §2 | 严重度与五种动作对照 |
| §3 | **豁免清单 9 条**（先查这个，别误伤） |
| §4 | **改写对照表 40 条**（触线 → 中性） |
| §5 | 详情页六段结构 + 首句正反例 |
| §6 | **输出格式**（严格规定，AI 照着填） |
| §7 | 六条硬约束 H1-H6 |
| §8 | 长度标准 + 葡语重音表 + 15 个翻译残留 + 11 条残句 |
| §9 | 反模板化检查 6 条 |
| §10 | 无法改文案的 6 类（出工单） |
| §11 | 平台处罚严重度对照 |
| §12 | **判定词表 68 组 / 1,439 词** |
| §13 | 五句话总结 |

**词表是从 `lexicon/term_groups.json` 自动生成的**（`tools/gen_prompt_lexicon.py` + `tools/inject_prompt_lexicon.py`），所以它永远与词库一致 —— 词库更新后跑一次注入脚本就同步。

校验：

```bash
python tools/gen_prompt_lexicon.py --check        # 1439 词全在文档里？
python tools/inject_prompt_lexicon.py --check      # 文档与词库同步？
```

## 5. 效果对照（真实跑出来的）

用 3 个故意设计的商品，规则引擎的判定如下：

| 商品 | 引擎结论 | 命中的规则 | 手册能判出来吗 |
|---|---|---|---|
| **P1** 化妆品<br>`Anti-Idade` + `100% garantia` + `Cura acne em 3 dias` + `Testado dermatologicamente` | REVIEW / high / require_evidence | SBR-RI-002, SBR-LV-011, SBR-MED-004, SBR-LV-007 | ✅ §12 功效宣称组 + §4 改写表 + §10 化妆品出工单 |
| **P2** 菜刀<br>`Faca profissional` + `Reduz o esforço` + `Fechamento seguro` | REVIEW / medium / flag_for_review | SBR-LV-007, SBR-LV-011, SBR-MED-004 | ✅ §3 EX-TOOLS 豁免 + EX-REDUZIR + EX-SEGURO —— **不误伤** |
| **P3** 背包<br>`Logo iFood` + `Redutor de entrada de água` | REVIEW / low / flag_for_review | SBR-LV-007, SBR-LV-011 | ✅ §12 侵权组（iFood）+ §3 EX-REDUZIR |

**P2 是关键测试** —— 菜刀、`Reduz`、`seguro` 全是命中词，但都是豁免。手册能正确区分"命中但豁免"和"命中且违规"。

> **说明**：自然语言判定**不可能 100% 等同于规则引擎**。引擎逐条比对 21 万词库 + 57 条规则 + 契约校验；手册覆盖 1,439 个触线词 + 豁免 + 改写表。
> **要最高准确度就用引擎**（见 `docs/CHATGPT_USAGE.md` 方案 A/B/C）；手册适合"快速过一遍"和"没法跑代码时"。

## 6. 三种方式怎么选

| | 读网页 + 自然语言（本方案） | Python 沙箱跑引擎 | 本地跑 |
|---|---|---|---|
| **要联网** | 只要 ChatGPT 能读网页 | ✗ 需要 DNS | ✗ |
| **要上传文件** | ✗ | ✗ | ✗ |
| **准确度** | 高（覆盖 1,439 触线词 + 豁免 + 改写表） | **最高**（21 万词 + 57 规则 + 契约校验） | **最高** |
| **速度** | 快 | 6-12 秒 | 6-12 秒 |
| **批量** | 有限（上下文长度） | 无限制 | 无限制 |
| **数据流向** | 商品内容进 OpenAI | 商品内容进 OpenAI | **不出本机** |

**建议**：
- 偶尔审几件、临时要结果 → **本方案**
- 一次审几百件、要可追溯报告 → 本地跑引擎，把报告喂给 ChatGPT 解读

## 7. 让判定更准的几个提示

| 想要 | 怎么说 |
|---|---|
| 补齐"未评估" | 「这几个商品没有图片，请把图片类规则标为未评估，不要当成通过」 |
| 要改写后的完整详情 | 「按 §5 的六段结构输出完整葡语详情，不要只给要点」 |
| 要英文版报告 | 「同样的判定，输出英文报告」 |
| 批量处理 | 「我接下来发 20 个商品，逐个按此判定，最后给汇总表」 |
| 复核上一轮 | 「重新检查上一轮的改写：有没有漏删、有没有引入新触线词、有没有误删豁免词」 |

## 8. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| ChatGPT 说读不到那个 URL | 平台策略或网络 | 换成 GitHub 网页地址（`github.com/.../blob/main/docs/CHATGPT_PROMPT.md`），让它读页面内容 |
| ChatGPT 没用手册的格式 | 没强调 | 「严格按手册 §6 的输出格式，不要自由发挥」 |
| 判定比引擎宽松 | 手册只含触线词表，不含 21 万词库 | 重要商品仍用引擎复核 |
| 改写后仍有问题 | LLM 改写会引入新词 | 「改完自己再查一遍 §12 的词表」 |
